## Product contracts, Outbox and versions

Three version-one Catalog product routing keys use existing envelope naming and strict complete projections. UUID/version linkage, deleted-state consistency, integer prices and source-sequence bounds are validated. Producer-specific canonical HMAC signing does not distribute Saga service secrets. Missing Catalog signing keys cannot be treated as empty signing keys by generic Saga authorization.

A new Catalog trigger captures each SQL insert/update/delete, atomically allocating a transactional committed sequence, advancing the durable product version, retaining a tombstone/current projection, appending immutable changes and inserting the existing Outbox envelope. Failed constraints and rollback leave none of these committed. Existing rows are captured at explicit migration time; seed/import writes after installation are captured too. Public Catalog Product responses remain unchanged.

Publishing is separately default-off and never runs inside a product transaction. Once the explicitly installed trigger exists, capture continues while publication/Search is disabled, avoiding untracked offline changes. Storage retention/compaction is deferred rather than deleting necessary history unsafely. Search description projection is bounded to 20,000 Unicode code points/80 KB UTF-8; Catalog's original text is preserved.

Elasticsearch uses deterministic UUID document IDs and atomic external versions, with no GET/compare/PUT race. Deletes become permanent hidden documents, not expiring Elasticsearch deletion markers. Source and derived PostgreSQL tombstones survive index loss/rebuild and prevent old events resurrecting deleted products. A legitimate recreated UUID advances its durable version. Per-generation write aliases/require_alias prevent silently creating a missing dynamic index. Confirmed missing retained generations can be marked LOST; active/candidate loss requires recovery. Cleanup is limited to exact owned retained/lost generations.

## Consumer and outage handling

Search consumes only the three Catalog bindings with bounded prefetch, validates signature/contract, persists monotonic state/immutable receipt fingerprint, writes registered indexes, persists receipt DONE and then returns for ACK. Duplicate events can reapply current state after index loss; external-version conflicts are harmless. Signature bytes are excluded from business receipt identity so legitimate transport re-signing does not redefine logical content.

Transient PG/HTTP/timeouts use existing finite durable retry/handoff/DLQ; permanent malformed/unsupported/forged/mapping-rejected data does not retry forever. Unknown delivery outcome may already have indexed, so retry uses the same ID/version. No unbounded in-memory retry list exists. Catalog mutations have no Elasticsearch dependency. Long outages exceeding retries require reviewed replay and/or authoritative rebuild/reconciliation; no automatic universal recovery claim is made.

## Mapping and public search

Strict mappings use keyword IDs, boosted standard-analyzed name text with keyword multi-field, description text, long integer prices/versions, date timestamps and deleted boolean. Public multi-match bool_prefix supports full-text/prefix/bounded fuzziness without arbitrary DSL/wildcards/scripts. Failed/partial/timed-out Elasticsearch searches yield 503, not false empty success.

Validated API `/search/products` supports bounded q, integer-paise min/max prices, chronological created-date ranges, allowlisted relevance/price/newest sorting, size 20/max 100 and encrypted authenticated sixty-second search_after cursors bound to the query. Every sort has an ID tie-breaker. Public results expose only the existing Product fields and pagination, not scores/index names/internal hashes. Live cursors are stable on a quiescent index, not PIT snapshots during concurrent mutations.

Every returned ID must currently exist in authoritative Catalog via a signed private read. This suppresses hard-deleted stale projections; lookup outage fails closed. Other searchable fields remain eventually consistent. There are no current private/draft/disabled fields; future visibility rules must extend the source check before deployment. Inventory remains independent and unmodified.

Gateway public Search routing remains independently opt-in. It reuses the global principal+SEARCH atomic Redis policies; default SEARCH burst/refill 120/minute is configurable. No second limiter or internal-header bypass is added. Gateway's Search-specific outer budget covers sequential bounded ES/Catalog RPCs; existing upstream settings remain unchanged. Internal exports/admin operations are not forwarded publicly.

## Rebuild, alias replacement, rollback and reconciliation

Durable phases register the candidate before reading the initial source watermark, load bounded UUID state pages, replay immutable changes through a later watermark, verify authoritative versions, audit candidate IDs/content, refresh and atomically replace the read alias. Concurrent later events write the registered candidate/new active index. Snapshot omission caused by concurrent row changes is covered by the immutable journal; old snapshots cannot overwrite newer external versions.

One active operation is protected by a unique constraint/advisory admission lock; workers use a session lock and persist page cursors. Crash before/after alias switching replays safely. Bounded dependency backoff pauses after ten failures and records the phase for explicit admin resume. Unresolved candidate mismatches block activation. Old read generation stays available during loading and retained for rollback; a rollback first repeats authoritative catch-up/verification before switching. Five registered generations cap retention; exact, audited operator cleanup is required.

Reconciliation repairs missing/stale/deleted-state projections from signed authoritative exports, catches up writes and audits index documents. Unknown/ahead/unrepairable data and count differences are reported without unverified product deletion; same-version corruption may require a fresh index. All admin routes use the shared verified admin role, strict empty mutation bodies and UUID operation IDs. They cannot select arbitrary index names. Private HMAC reads bind search caller, method, complete query/path and timestamp; Notifications' default signing bytes remain unchanged.
